# Wuxia Local — Project Memory v3.1

**Дата:** 7 ноября 2026 · основано на v3.0. Здесь только то, что изменилось или уточнилось. Принципы v3.0 (Rust, локально, бесплатно, без инъекций, бюджетные ПК, установщик без PowerShell) сохранены без изменений.

## 1. Что изменено в архитектуре и почему

| Тема | v3.0 | v3.1 (реализовано) | Причина |
|---|---|---|---|
| OCR для MVP | PaddleOCR (ONNX) — основной кандидат | **Windows.Media.Ocr**, а PaddleOCR — второй движок за тем же интерфейсом `OcrLine` | Нулевой размер дистрибутива, есть координаты слов, нет ONNX-моделей и DLL. Это снимает главный риск MVP. Paddle добавим, если на реальных скриншотах WWM точность окажется недостаточной. |
| Захват | Windows.Graphics.Capture | **GDI BitBlt прямоугольника** + `WDA_EXCLUDEFROMCAPTURE` у оверлея; WGC — следующий бэкенд | Полоса субтитров снимается за 1–3 мс без D3D. Оверлей исключён дважды: аффинити окна и layered-окно без `CAPTUREBLT`. |
| Обнаружение новой реплики | «обнаружение нового текста» | Отпечаток **только по пикселям текста** (светлый ненасыщенный пиксель с тёмным соседом) + N стабильных кадров + проверка похожести OCR-текста | Движущаяся 3D-сцена за субтитрами не вызывает лишний OCR. Эффект «печатной машинки» дожидается конца строки. |
| Устаревшие переводы | требование | Номер реплики + `abort()` задачи + стриминг: при закрытии соединения llama-server прекращает генерацию | Новая реплика всегда побеждает. GPU не тратится на ненужный ответ. |
| Промпты | — | Для Hy-MT — **официальные китайские шаблоны** (термины, контекст, стиль). Для Qwen и других instruct-моделей — системный промпт с правилами уся: Палладий, чэнъюи, 文言, обращения | Переводческие модели обучены на фиксированных шаблонах; свободный промпт ухудшает качество. |
| Глоссарий | идея | TSV, поиск сначала самых длинных совпадений, в промпт попадают только встреченные термины (≤24); проверка соблюдения с учётом склонения | Короткий промпт работает быстрее, а для 1.8B-модели и точнее. |
| Кэш | — | Ключ (модель, тип текста, исходник). **Исправления пользователя** имеют приоритет. Хранение — append-only TSV | Справедливое сравнение моделей; переживает падения; редактируется в Блокноте. |
| Имя говорящего | — | `Имя：реплика` — имя переводится отдельно и кэшируется | Имена повторяются постоянно и не засоряют контекст. |
| Загрузка моделей | — | `llama-server -hf repo:quant` в нашу папку, после первой загрузки путь к `.gguf` записывается в конфиг → дальше полностью офлайн | Не нужно писать свой загрузчик и угадывать имена файлов. |
| Нагрузка на игру | требование | Приоритет BELOW_NORMAL, половина ядер, пауза при свёрнутой игре, Job Object (сервер не остаётся висеть) | Бюджетные ПК. |
| Выбор модели | принцип | **Встроенный бенчмарк**: одни и те же реплики → отчёт Markdown бок о бок + задержки + нарушения глоссария | Решение по качеству принимается на реальных строках, а не по рейтингам. |

## 2. Модели — актуальные факты (проверено 7.11.2026)

* **Hy-MT2** (Tencent) выпущена 21.05.2026 в размерах 1.8B, 7B и 30B-A3B, лицензия Apache-2.0. Есть GGUF Q4_K_M (1.8B — 1,13 ГБ), Q6_K, Q8_0 и экстремальные 2-bit/1.25-bit.
* Рекомендуемые параметры для 1.8B и 7B: temperature 0.7, top_p 0.6, top_k 20, repetition_penalty 1.05. Системного промпта нет.
* ⚠ Карточка GGUF указывает, что нужно **STQ-ядро из llama.cpp PR #22836**. Перед релизом проверить, что выбранная сборка llama.cpp загружает Q4_K_M. Если не загружает, собрать llama.cpp из ветки с PR в CI. Запасной вариант — Qwen3.5 2B.

## 3. Открытые риски

1. Античит WWM: программа не трогает процесс игры, но поверх неё висит topmost-окно. Проверить, что это не вызывает предупреждений.
2. Эксклюзивный полноэкранный режим не поддерживается, нужен режим окна без рамки.
3. Точность Windows OCR на стилизованных шрифтах WWM → набрать 50–100 реальных скриншотов и сравнить с PaddleOCR.
4. Проверить переносы и выравнивание русского текста на 1080p, 1440p и 4K при масштабе Windows 125–150 %.
