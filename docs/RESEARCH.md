# Что взять у других открытых переводчиков

Обзор от 7 ноября 2026. Для каждого проекта отмечено, что у него лучше, чем у нас, и стоит ли это переносить.

| Проект | Что это | Что полезно нам |
|---|---|---|
| **Translumo** (C#, Apache-2.0, ~3,7k ★) | Экранный переводчик субтитров в реальном времени | Несколько OCR одновременно (Tesseract, Windows OCR, EasyOCR) и ML-модель, которая оценивает результаты и выбирает лучший. Автор советует всегда держать Windows OCR включённым как самый лёгкий. |
| **Translumo-LLM** (форк) | То же + LLM (OpenAI/Anthropic/Gemini/Ollama) | Режим «как Google Lens»: выделил область → построчный перевод поверх. Похоже на наш Interface Mode. |
| **LunaTranslator** (C++/Python, GPL-3, ~11k ★) | Переводчик визуальных новелл | HOOK-извлечение текста (нам запрещено концептом), OCR, LLM. Сильная сторона — **словари оптимизации перевода для каждой игры**: исправление ошибок OCR до перевода, замены после перевода, имена собственные. |
| **Game-Changing Translator** | Экранный переводчик с TTS | Настраиваемые «порог стабильности текста», «таймаут очистки», **«удалять мусор после последнего знака препинания»**, **окно предпросмотра OCR** (что видит распознавание). Функция **Find Subtitles**: сканирует экран и сам находит, где появляются субтитры. |
| **RSTGameTranslation** (MIT) | OCR + LLM для игр | Резервный переводчик, если основной тормозит; распознавание имён персонажей. |
| **Comic Translate / Koharu / manga-image-translator** | Перевод манги | **LLM получает весь текст страницы сразу**, а не по строке: согласованнее и быстрее. Стирание исходного текста **инпейнтингом** (LaMa) вместо плоской заливки. Подбор размера шрифта под рамку. Koharu написан на Rust и использует llama.cpp, как мы. |
| **MangaTranslator** | Перевод манги | Уже поддерживает **Hy-MT2** и подставляет те же рекомендованные параметры, что и мы. Это подтверждает выбор модели. |
| **ocr-rs / RustO!** (Rust, Apache-2.0/MIT) | PaddleOCR PP-OCRv5 на чистом Rust (MNN) | Готовый путь к PaddleOCR без Python и OpenCV: мобильная модель ~28 МБ, китайский + английский. Это наш кандидат на второй OCR-движок. |

## Решения для Wuxia Local

**Сделать сейчас (дёшево, заметный эффект):**
1. **Пакетный перевод экрана.** В Interface Mode отправлять все строки экрана одним запросом с разделителями (у Hy-MT2 есть официальный шаблон «сохрани число разделителей»). Один запрос вместо 30–80: быстрее и терминология согласованнее.
2. **Словарь исправлений OCR и замен после перевода** (`fixes.tsv`): `ocr<TAB>錯<TAB>对` и `ru<TAB>Цзянху<TAB>цзянху`. Работает как у LunaTranslator, но без кода.
3. **Срезать мусор после последнего знака препинания** — частая ошибка OCR на рамках диалоговых окон.
4. **Окно «Что видит OCR»** в панели: последний кадр области и распознанный текст. Без него пользователь не поймёт, почему не работает.

**Сделать в 0.3:**
5. **PaddleOCR PP-OCRv5 через ocr-rs** вторым движком. Режим «оба»: если результаты Windows OCR и Paddle расходятся, брать вариант с большей долей иероглифов и меньшим числом мусорных символов (упрощённый Translumo, без ML).
6. **Автопоиск области субтитров** (как Find Subtitles): несколько кадров нижней трети экрана → где меняется светлый текст с обводкой, там и субтитры.

**Не делать:**
- HOOK и инъекции — запрещены концептом и рискованны из-за античита.
- Тяжёлый инпейнтинг (LaMa, FLUX) в реальном времени — слишком дорого для бюджетных ПК. Позже, возможно, лёгкое размытие фона под маской.
